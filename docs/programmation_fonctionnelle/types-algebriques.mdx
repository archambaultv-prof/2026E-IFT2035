# Types algébriques

Les **types algébriques de données** (*algebraic data types*, ou ADT) sont la
façon dont Haskell permet de définir de nouveaux types. Il en existe deux
variétés fondamentales : les **types produits** et les **types sommes**. On les
combine librement pour construire des structures de données riches.

## Types produits — regrouper plusieurs valeurs

Un **type produit** regroupe plusieurs champs en une seule valeur — exactement
comme les attributs d'une classe.

```haskell
data Point = Point Double Double
```

La valeur `Point 3.0 4.0` contient *toujours* deux `Double` : une coordonnée x
**et** une coordonnée y. Les deux champs sont présents simultanément.

:::tip[Comparaison avec Python]
En Python, on modéliserait cela avec une classe :

```python
class Point:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

p = Point(3.0, 4.0)
```

En Haskell, pas besoin de méthode `__init__` : le constructeur `Point` joue ce
rôle directement.

```haskell
p :: Point
p = Point 3.0 4.0
```
:::

Autres exemples de types produits :

```haskell
data Personne  = Personne String Int          -- nom ET âge
data Rectangle = Rectangle Double Double      -- largeur ET hauteur
data Couleur3  = Couleur3 Int Int Int         -- rouge ET vert ET bleu
```

On dit « produit » parce que l'ensemble des valeurs possibles est le *produit
cartésien* des ensembles de chaque champ. Un `Rectangle` peut avoir n'importe
quelle largeur **combinée** à n'importe quelle hauteur.

## Types sommes — choisir entre plusieurs formes

Un **type somme** (*sum type* ou *union discriminante*) exprime qu'une valeur
peut prendre **l'une ou l'autre** d'un ensemble de formes. C'est là que Haskell
(et la programmation fonctionnelle en général) se distingue nettement de Python
ou Java.

```haskell
data Jour = Lundi | Mardi | Mercredi | Jeudi | Vendredi | Samedi | Dimanche
```

Un `Jour` est *soit* `Lundi`, *soit* `Mardi`, *soit* … — jamais plusieurs à la
fois, et jamais rien d'autre.

:::tip[Comparaison avec Python]
Python n'a pas de type somme natif. La façon la plus proche serait une
énumération :

```python
from enum import Enum

class Jour(Enum):
    LUNDI    = 1
    MARDI    = 2
    MERCREDI = 3
    JEUDI    = 4
    VENDREDI = 5
    SAMEDI   = 6
    DIMANCHE = 7
```

Mais les énumérations Python ne peuvent pas porter des données différentes
selon le cas (voir la section suivante). Les types sommes de Haskell sont
beaucoup plus expressifs.
:::

On dit « somme » parce que le nombre total de valeurs possibles est la *somme*
des valeurs de chaque alternative.

## Types sommes avec données — le vrai pouvoir

Chaque alternative (constructeur) d'un type somme peut porter ses **propres
données**, et chaque alternative peut avoir un nombre de champs différent.

```haskell
-- Une forme géométrique : soit un cercle (avec son rayon),
-- soit un rectangle (avec sa largeur et sa hauteur)
data Forme = Cercle Double | Rectangle Double Double
```

- `Cercle 5.0` — un cercle porte *un* `Double` (son rayon).
- `Rectangle 3.0 4.0` — un rectangle porte *deux* `Double`.

Ces deux constructeurs font partie du **même type** `Forme`, mais ils ont des
structures internes différentes.

```haskell
ghci> :type Cercle
Cercle :: Double -> Forme

ghci> :type Rectangle
Rectangle :: Double -> Double -> Forme

ghci> Cercle 5.0
Cercle 5.0

ghci> Rectangle 3.0 4.0
Rectangle 3.0 4.0
```

:::tip[Comparaison avec Python]
En Python, on simulerait cela avec une hiérarchie de classes et de l'héritage :

```python
class Forme:
    pass

class Cercle(Forme):
    def __init__(self, rayon: float):
        self.rayon = rayon

class Rectangle(Forme):
    def __init__(self, largeur: float, hauteur: float):
        self.largeur = largeur
        self.hauteur = hauteur
```

En Haskell, tout cela s'écrit en **une ligne**. Et contrairement à Python, le
compilateur *garantit* qu'on a traité tous les cas possibles lors du filtrage
par motifs.
:::


## Types algébriques — produit ET somme ensemble

La plupart des types intéressants combinent les deux. Chaque constructeur d'un
type somme peut lui-même être un type produit (porter plusieurs champs).

```haskell
data Forme = Cercle Double              -- rayon
           | Rectangle Double Double    -- largeur, hauteur
           | Triangle Double Double     -- base, hauteur
```

C'est à la fois une somme (trois alternatives) et, pour chaque alternative, un
produit (plusieurs champs).

:::tip[Syntaxe Haskell — `data`]
La déclaration `data` crée à la fois le **type** et ses **constructeurs**.
Les constructeurs commencent toujours par une **majuscule** ; les variables de
type commencent par une **minuscule**.

```haskell
data Couleur    = Rouge | Vert | Bleu         -- somme pure (énumération)
data Point      = Point Double Double          -- produit pur (un seul constructeur)
data Maybe a    = Nothing | Just a             -- somme : absence OU présence
data Either a b = Left a | Right b             -- somme : deux alternatives typées
```

`Either a b` est utile pour représenter un résultat qui peut être de deux
natures différentes — par exemple une valeur (`Right`) ou un message d'erreur
(`Left`).
:::

## Types polymorphes

Un type peut avoir des **paramètres de type** (variables de type), ce qui le
rend générique :

```haskell
data Maybe a = Nothing | Just a
```

`Maybe a` représente une valeur optionnelle de type `a` :
- `Nothing` — aucune valeur
- `Just x` — la valeur `x`

```haskell
ghci> :type Nothing
Nothing :: Maybe a

ghci> :type Just
Just :: a -> Maybe a

ghci> Just 42
Just 42

ghci> Just "bonjour"
Just "bonjour"
```

`Maybe` est le type standard de Haskell pour remplacer les valeurs `None` de
Python ou les références nulles de Java, mais de façon *sûre* : le compilateur
oblige le code appelant à vérifier si la valeur est présente ou non.
